# 学习进度持久化与 DeepSeek 分析

> 当前前测、全部单元、后测与证据画像已由后端统一提供，操作以[完整学习链路](server-unit-demo.md)为准。本文的 AI 分析仅针对当前八题前测。

## 运行和配置

账号服务与学习服务共用 FastAPI。前端仍执行 `npm run dev`，后端执行 `python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000`。默认演示账号为 `admin / admin`。

DeepSeek 配置文件位于 **`code/backend/.env`**，新环境需从同目录 `.env.example` 创建；已有配置保留原值。填入自己的 Key 后重启后端：

```dotenv
DEEPSEEK_API_KEY=填入你的真实Key
DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_TIMEOUT=45
```

配置由后端 `Settings` 读取，路径不随启动工作目录变化，进程环境变量优先。不要使用 `VITE_` 前缀放置密钥。`.env` 被 Git 忽略；API Key 不进入前端、JSON 学习记录、请求提示或错误响应。上述文件配置目前用于 DeepSeek；原有 `OWL_*` 账号参数仍通过进程环境变量设置。

默认模型按 2026-11-02 查阅的 [DeepSeek 模型文档](https://api-docs.deepseek.com/quick_start/pricing/) 采用 `deepseek-flash`，可在配置文件中修改。请求使用官方 `https://api.deepseek.com/chat/completions`，按 [JSON Output 文档](https://api-docs.deepseek.com/guides/json_mode/) 指定 JSON 模式、格式示例和输出上限。没有 Key 时不会调用模型。

新环境先将 `code/backend/.env.example` 复制为 `code/backend/.env`。Docker 环境可将这三个变量注入 backend 服务；本次 Compose 已引用后端 `.env`。现有命名卷保存学习数据。Docker 部署尚未实机验收。

## 保存什么

登录用户的以下内容保存在账号 JSON 文件同目录的 `learning.json`：

- 当前流程阶段与题目位置；已提交答案、当前选择及提交状态。
- 前测结果由答案重算，浏览器不能向分析接口指定任意成绩。
- 所选主题；每个主题已自行标记完成的单元编号。
- 已生成的 DeepSeek 分析、模型名及生成时间。

记录以服务端会话确定的用户 ID 为键；接口不接受目标用户 ID。刷新、重新登录、重启后端后可恢复。游客仍只保留当前页面状态，游客历史不自动合并到账号。

前端逐次串行保存草稿与页面状态，正式成绩通过测验提交接口保存。前端逐次串行保存最新状态，仅在失败时显示提示并支持重试；未保存时离开页面会触发浏览器提示，退出按钮暂不可用。网络中断且直接关闭页面时，尚未提交到服务端的修改无法保证保留；本轮不实现离线同步。

仓储采用文件锁、原子替换及 revision 乐观并发控制。多个页面编辑同一账号时，旧版本返回 409，页面提示加载最新保存的进度，不静默覆盖。重新前测通过服务端 reset 接口重开当前测评与方向设置，保留各主题正式通过记录和历史作答；前端不能直接取消或授予完成状态。内容版本为 1，后续题库或单元编号变化必须显式迁移。

## 分析流程与边界

完成前测并成功保存作答后，系统自动调用 DeepSeek，无需点击分析按钮。分析仅展示在诊断页、逐题回顾之前，或从 Home 打开的前测报告页，包括表现概述、优势、优先巩固项、每道错题的分析和建议、2–3 个由易到难的练习及自查标准。等待分析时仍可选择方向。

这是受约束的学习分析工作流，尚未接入 RAG、开放工具调用或自动修改学习计划。模型不能修改分数、进度和账号数据。分析输入不含账号、昵称、密码、会话令牌；包括每道题的题干、选项、实际选择、正确答案、判分和解析，以及测评统计。固定 8 题不能代表正式汉语能力或口语水平，完成标记也不能代表掌握度。

后端检查完整响应和 JSON 结构，拒绝空文本、截断、错误字段及过长内容。超时、鉴权失败或异常输出显示不可用提示，不用假内容冒充 AI 结果，预设计划仍可使用。同一学习证据的分析会缓存；前测作答变化后失效。分析期间证据变化时丢弃旧结果，防止覆盖新状态。每次请求最多调用模型一次，不自动重试。

## API

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | `/api/v1/learning/progress` | 返回当前账号 state、revision、updated_at、analysis |
| PUT | `/api/v1/learning/progress` | 传 state 与 revision；校验状态，更新并返回新版本 |
| POST | `/api/v1/learning/analysis` | 根据当前保存进度分析；有缓存则直接返回 |

未登录 401；非法进度 422；版本冲突或过时分析 409；未完成前测 400；未配置模型或供应商故障 503。变更接口沿用同源校验，响应不缓存。

## 验收

1. 登录后答到中途，保存完成后刷新，检查题目、选择、提交状态和解析恢复。
2. 完成前测并选择方向，标记一个单元完成；退出后再登录，检查计划和完成数量。
3. 换一个账号，确认无法看到前一账号进度；重启后端后再检查恢复。
4. 两个页面编辑同一账号，检查旧版本提示冲突；断网保存失败后恢复连接并重试。
5. 未填 Key 时完成前测，确认提示未配置且进度仍在。填写有效 Key、重启后端后点击重试分析，检查结果来源、生成内容与刷新恢复。

自动化测试使用临时 JSON 文件和模拟 DeepSeek HTTP 响应，不消耗真实模型额度。真实模型连通性须在用户配置有效 Key 后验证。

## 登录首页与首次学习设置

登录后首先进入 Home，而不是直接打开测评。Home 从当前账号的保存状态读取 `onboarding_complete`：

- 未完成：显示三步设置卡（前测诊断 → 兴趣方向 → 确认规划），点击后恢复上次进行到的位置。
- 完成前测、确认方向并查看规划后，点击“完成设置，进入首页”保存完成标记。
- 已完成：Home 展示当前方向、下一未完成单元、完成比例、前测表现、前测报告回看入口与学习单元列表。点击继续学习直接打开对应单元。
- 后续修改方向不会清除完成标记。方向选择使用草稿值，确认前不会替换现有计划；主动重新前测才重新进入设置状态。各方向已有单元标记继续保留。
- 兼容旧进度：没有完成标记但已处于 plan 阶段的记录视为已完成；其他旧记录继续显示设置引导。游客仍直接体验原流程。

Home 导航状态不作为学习进度保存，因此刷新或重新登录始终先到首页。已有分析直接读取缓存；没有分析的已完成前测会在恢复进度后自动分析。修改方向、单元进度不触发前测分析。相同证据的失败不循环重试，仅显示“重试分析”；保存失败时先恢复保存。重新前测或证据变化后，旧请求结果不会显示到新测评中。

## 提示词设计

版本化系统提示词：`code/backend/app/integrations/llm/prompts/assessment.py`，当前版本 `assessment-v5`。

- 先比较每题实际选择与正确规则，再归纳共性，不能只按总分套模板。
- 用“可能混淆”表达错误原因的假设；不推测国籍、母语、态度，不判定 HSK 或发音水平。
- 每道错题恰好对应一条反馈；全对时不制造薄弱点，改做迁移与复习；全错时从基础开始。
- 练习按辨认、对比、应用逐步推进，包含例子、拼音、对应题目和自查标准。只依据前测作答，不推测兴趣。
- 生成的是个性化建议与微练习，不替换当前预设课程。

服务端校验错题覆盖、题目引用、字段结构和长度。缓存指纹包括逐题答案、题目内容及提示词版本；同分但错题不同的作答不会共用分析，旧版本分析会失效。前后端题库一致性由自动化测试检查。

详细的阶段介入、界面位置、提示词分工与后续范围见 [Agent 介入设计](agent-intervention-design.md)。
