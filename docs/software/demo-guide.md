# 下周交互原型：运行、验收与汇报

## 学习路径、单元小测与后测（更新）

当前演示流程为：前测与诊断 → 选择方向 → 学习规划 → 后测 → 诊断报告。

旅游出行、日常生活、校园交流、古诗入门各有 5 个单元：前两个单元建立基础表达，中间两个单元进行情境练习，最后一个单元完成综合任务。每个单元提供词汇与拼音、核心句型、情境对话、认读与迁移练习，以及 2 道单元选择题。小测全部答对后自动记录完成进度；提交后显示正确答案和解释，可以重做。

学习规划底部与登录后的首页均提供后测入口。每个方向的后测有 10 题，包含单元知识回顾与新的迁移情境题；全部作答后提交，展示实际得分和逐题解析。允许提前尝试后测，也可以返回规划复习。

提交后测后点击“查看诊断报告”，进入独立报告视图。分数、正确题数与完成单元数来自当前学习记录；能力画像、练习建议与一周安排为固定示例，并在页面标明。前测与方向后测考查内容不同，不直接计算前后测提升分数。

登录用户通过现有进度接口保存各方向的单元小测与后测记录，刷新后从首页继续；游客记录保留在当前页面会话中。更新后端进度模型后需重启 FastAPI（开启 `--reload` 时会自动重载）。

建议演示：完成前测 → 选择任一方向 → 展开单元并完成小测 → 查看进度变化 → 开始后测 → 提交并回顾解析 → 查看报告 → 返回规划或重做后测。

## 范围与运行

本轮实现前测、实际计分诊断、兴趣选择、预设计划及单元详情。沿用 8 道拼音与声调题，不评估听说读写综合能力。旅游、日常生活、校园交流、古诗各有 5 个预设单元。学习计划按主题读取；前测不同分数展示不同复习建议。

在 `code/frontend` 执行 `npm ci`、`npm run dev`，打开终端显示的本地地址。游客模式的学习流程无需后端、数据库或模型密钥；注册登录需要同时启动 FastAPI 后端，见 [账号说明](accounts.md)。`npm run build` 生成静态产物，`npm run preview` 可预览。登录用户刷新后恢复已保存进度；游客刷新后重置。DeepSeek 可选分析的配置见 [接入说明](learning-agent.md)。

## 架构与技术待确认项

当前路径：Vue 页面 → `src/shared/api/demo.ts` Promise 函数 → 本地固定内容。`getQuestions` 获取题目，`submitAnswers` 校验答案并计算诊断，`getTopics` 读取主题，`getPlan` 读取预设计划。页面持有作答结果与所选主题。未来用 HTTP 替换此适配层时保持返回契约；正式计分需迁往后端，公开题目接口不返回答案。当前本地答案可见，仅适用于演示。

既有 [架构建议](architecture.md) 中 FastAPI、PostgreSQL、模型、Mem0 和 pgvector 不构成本轮启动依赖。五人需共同评审下列事项；这里不代替实际团队确认：

| 待评审事项 | 当前依据 | 通过条件 |
| --- | --- | --- |
| 本轮技术可运行性 | Vue + 本地 Promise mock | 另一成员在主讲机器上复现完整流程 |
| 后续接口边界 | mock 四类调用及既有 API 草案 | 对齐 DTO、错误格式、服务端计分与用户状态方案 |

## 账号验收

注册新账号，退出后重新登录；检查重复账号和错误密码提示；刷新页面确认登录恢复；退出后确认回到登录入口。可使用游客入口展示原有学习流程。账号文件不得包含明文密码。

## 手工验收

1. 进入前测，未选答案不能提交；选择后提交，显示反馈与解析，不能重复修改已提交答案。
2. 连续完成 8 题；全对为 100 分，全错为 0 分，答对 7 题为 88 分；查看三个分项和逐题解析。
3. 核对不同分数的建议，点击重新测评，进度和答案清空。
4. 从诊断进入方向选择；未选方向不能确认。分别选择四个方向，确认后标题、单元和内容匹配。
5. 展开单元查看目标、拼音词汇、例句和练习建议；修改方向后更新计划，诊断分数保持不变。
6. 从计划重新前测，原主题与计划清空；游客刷新回到初始状态；登录用户刷新恢复已保存进度。
7. 在手机宽度和键盘操作下核对选择、按钮、展开详情；页面持续显示演示数据说明。
