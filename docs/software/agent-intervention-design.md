# Agent 在学习流程中的介入设计

## 产品定位与本轮范围

Agent 是流程中的辅导能力，围绕具体学习任务出现。每次介入有触发事件、证据、明确产出和退出位置；不设置跨页常驻的“Agent 学习分析”面板，也不自动弹出聊天窗口。

本轮实际实现：前测提交后自动分析，诊断页展示完整报告；Home 的“学习起点”提供“查看前测报告”，打开独立回看页。选择方向和规划页移除重复分析；切换方向、导航、标记完成不重新生成前测报告。报告缓存只依赖前测题目、答案及提示词版本。等待报告时仍可继续设置或标记进度。

下表中其余 Agent 能力属于后续设计，尚未接入；当前方向选择、预设规划、单元完成标记继续按原型逻辑运行，不展示虚构的 AI 结果。

## 介入点与页面位置

| 阶段 | 触发与页面位置 | 依据与产出 | 退出与限制 | 状态 |
| --- | --- | --- | --- | --- |
| 前测作答中 | 不主动介入 | 固定题目与提交后的规则解析 | 不调用模型提示答案；当前演示仍保留即时解析，正式前测将另行设计 | 已实现固定解析 |
| 前测完成 | 全部作答成功保存后自动触发；诊断页分数下方 | 逐题选择、标准答案、解析；归纳错题、给 2–3 个微练习和自查标准 | 可继续选方向，不必等待；离开后后台请求完成仍保存；失败仅提供重试 | 已实现 Agent |
| 选择方向 | 默认不介入；用户点“帮我比较方向”才在方向卡片旁展开 | 用户勾选的候选方向、可用内容、明确目标；比较场景与学习收益，最多推荐两个 | 用户自行确认；不根据拼音分数禁止古诗等兴趣，也不重复诊断 | 后续 |
| 确认规划 | 方向、时间预算和目标确认后，主动点“生成适合我的安排” | 诊断要点、目标、每日时间、可用单元及先修关系；输出顺序、练习量、推荐理由 | 在规划页预览；用户接受后才替换计划。当前缺少时间预算和完整内容库，继续展示预设计划 | 后续 |
| 单元学习 | 用户点某个词句旁的“解释一下” | 当前句子、上下文、课程释义与学习阶段；简明解释、拼音、一个同类例子 | 就地展开、可收起；一次只解释当前对象，不弹整份报告 | 后续 |
| 练习遇到困难 | 用户点“给我提示”；同一知识点连续两次错误时仅邀请“需要一点提示吗？” | 当前题目、用户尝试、已用提示级别；逐步给规则线索、异题示例、步骤、完整讲解 | 不因停留时间长就认定困难；每次由用户决定是否继续提示；完整答案需明确请求或完成提交 | 后续 |
| 单元练习结束 | 有实际练习结果后，结果页自动生成简短反馈 | 正确率、知识点、提示使用、独立作答表现；一条进步、一项待练内容、下一步 | “标记完成”不足以触发能力评价；至少有有效作答后才总结 | 后续 |
| 复习与调整 | 出现到期复习、或同一知识点跨两次练习持续失误时，Home 显示一张行动卡 | 历次作答与复习间隔；建议复习具体知识点或调整一个单元 | “去复习 / 稍后”；调整课程需用户确认。没有新证据不重复建议 | 后续 |

连续两次错误、跨两次练习等阈值是原型起点，需通过试用调整，不作为教学有效性的验证结论。汉语水平、任务认知层级、提示强度分别记录，不能互相替代。

## 典型用户路径

1. 新用户完成前测：分数立即出现，下方显示“正在分析作答”。报告完成后给出本次错题解释和针对性练习。
2. 进入方向页：只看主题内容并做选择。前测报告留在诊断环节，不继续占据页面。
3. 进入规划页：只看课程目标、顺序和安排。本轮使用预设计划，不能声称 Agent 已按能力生成课程。
4. 回到 Home：继续学习为主操作；历史报告从学习起点卡片回看，不再单设 AI 分析卡片。
5. 后续实际学习中：遇到词句或练习困难，辅导出现在对应词句或题目旁。完成练习后才评价新表现。

## 按介入任务拆分提示词

不同任务分别调用模型、分别缓存；不把所有状态拼进一段通用提示词。

| 任务 | 提示词核心约束 | 结构化输出 |
| --- | --- | --- |
| assessment_review | 只根据本次逐题证据解释；错误原因是可能性；全对不造弱项；不推断发音、HSK、母语或态度 | summary、strengths、focus_areas、question_feedback、practice_tasks、next_steps |
| direction_compare | 只比较候选主题与明确目标；缺失目标先问一个问题；不从分数臆测兴趣 | clarification 或 comparisons、recommendations、reasons |
| plan_proposal | 只引用真实单元 ID；遵守时间预算和先修关系；说明依据；无资料时不编造课程 | units、schedule、rationale、changes、requires_confirmation |
| contextual_explanation | 聚焦用户选中的词句；依据课程原文与检索资料；简单语言解释，附一个例子 | explanation、pinyin、example、source_ids |
| progressive_hint | 遵守当前提示级别；前两级不直接透露本题答案；不把用过提示后的答对当成独立掌握 | hint_level、hint、next_hint_available |
| session_review | 只总结本轮练习；区分独立完成与辅助完成；不给无依据的能力标签 | observed_progress、practice_focus、next_action |
| revision_proposal | 基于跨次证据提建议，不直接写课程；说明建议调整的内容、原因、代价 | evidence_ids、proposed_changes、reason、requires_confirmation |

已实现的 assessment_review 提示词在 `code/backend/app/integrations/llm/prompts/assessment.py`，版本 `assessment-v3`。输入不含主题或自报单元进度，历史报告不会随这些状态变动而改写。每道错题须恰好出现一次；练习必须引用输入题目；服务端负责校验结构和引用，评分始终由规则计算。

后续输入文本一律当作数据，不当作系统指令；内容解释必须提供可核验的课程或检索来源。提示与练习建议可自动呈现，但模型无权直接修改成绩、课程完成状态或用户计划。

## 调度、存储与失败处理

- 前测报告在成功保存后触发；同一页面相同证据的失败不循环重试。已有结果直接读取。
- 前测报告独立于当前兴趣和学习进度；导航、选方向、完成标记不产生新的分析请求。重新作答、题目或提示词版本变化才使缓存失效。
- 分析失败只在诊断/报告页显示重试入口，不向方向页、规划页传播错误提示，不阻塞继续学习。
- 后续建议按 task_type、source_event_id、evidence_version、prompt_version 保存，附状态、结果、创建时间和用户接受/忽略状态。引入后台任务时再增加跨页面请求去重、速率限制和取消机制；当前接口为同步请求，不宣称已实现后台队列。
- 实践数据后续增加 attempt_id、item_id、knowledge_point、answer、correct、hint_level、submitted_at；不将单元自行标记完成作为掌握度证据。
- 页面只渲染与当前任务相关的输出；Home 后续最多一张待行动建议，已忽略的建议不立即再出现。

## 本轮验收

- 诊断页有逐题分析，方向页和规划页没有完整分析面板。
- Home 不展示独立 Agent 卡片；“查看前测报告”可回看，不改变当前课程阶段和方向。
- 改方向、标记完成不会再调用模型，也不会清空已有报告。
- 未保存最终答案不分析；失败可重试；重新测评后旧请求不能覆盖新作答。
- 前后端题库一致、同分不同答案缓存不同、题目引用与错题覆盖校验通过。
