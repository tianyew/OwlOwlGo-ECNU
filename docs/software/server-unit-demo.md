# 完整学习链路：运行与验收

原首单元试点已扩展到 **8 题前测 → 四个方向共 20 个单元 → 每方向 10 题后测 → 真实作答画像**。
题库、判分、正式提交和完成状态由后端负责；前端负责输入和展示。
课程仍是预设内容，学习记录当前存储为 JSON。账号、会话和限流已接入 PostgreSQL；RAG 或动态课程生成未实现。启动前先按[账号说明](accounts.md)准备数据库与表结构。

## 启动

终端一，在仓库根目录执行：

```bash
cd code/backend
source .venv/bin/activate
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

终端二，在仓库根目录执行：

```bash
cd code/frontend
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

访问 <http://127.0.0.1:5173>。判分、完成状态和画像不调用模型，不需要 DeepSeek Key。
可选的 AI 建议仍只分析本次八题前测，配置见[学习分析说明](learning-agent.md)。
AI 不可用时可以继续选择方向和学习。游客可预览课程与题目，登录后才能提交和保存。

## 浏览器验收

建议注册新的测试账号，以便观察首次作答与画像证据。

1. 从首页进入学习设置，开始前测。答案按题分页，完成八题后一次提交。
   未作答完不能提交，正式提交前不显示正确答案与解析。
2. 前测中途选择答案、切换页码，等待右上方显示「进度已保存」后刷新。
   从首页恢复设置，应恢复已选答案与页码，尚未形成正式分数或画像证据。
3. 完成前测并提交，检查总分、分项记录和逐题反馈；若只错一题，应为 **88 分**。
   AI 建议等待中或不可用时，仍可进入方向选择。
4. 选择「旅游出行」，确认方向，打开第一个单元「礼貌问路与方位」。
   第一题选「车站多少钱？」，第二题选「银行的位置」后提交。
   应得到 **50 分、答对 1 / 2、尚未通过**，完成数量仍为 **0 / 5**。
5. 点击「重新练习」，第一题改选「请问，车站在哪儿？」，第二题仍选「银行的位置」。
   应得到 **100 分**，完成数量变成 **1 / 5**。再练答错只改变最近成绩，已通过记录保留。
6. 刷新后，从首页单元列表打开第一个单元，成绩和解析应恢复。
   未提交的小测选择也会随进度保存为草稿；网络失败时页面会保留选择并提示重试。
7. 按单元顺序完成余下四个单元，每个单元两题全部答对即通过。
   后测可提前尝试；**方向完成**要求五个单元均通过，且该方向后测曾达到 **60 分**。
8. 进入方向后测，完成十题并提交，打开学习报告。
   报告展示实际后测成绩、单元完成情况和真实画像，不再显示固定 85/80/70 示例分数。
   前测与后测测量内容不同，不计算直接提升百分比。
9. 从首页或规划页点击「查看学习画像」。应展示七个语言维度、六类认知目标，共 42 格。
   尚无证据的格子应为「— / 尚未测评」。功能性阅读、非连续性文本、文言文和书面表达目前没有题目覆盖。
10. 对同一小测反复练习：不同题目数不增加，最近练习表现和重复次数变化。
    后测中复用的单元题即使改变了选项顺序，也不增加新的证据覆盖。
11. 修改到「日常生活」「校园交流」「古诗」，逐一验证单元取题、判分、后测和报告；切换方向保留各方向已通过记录。
12. 点击「重新前测」：当前前测、方向选择和首次设置会重置，历史作答、画像证据与已通过单元保留。
    新一轮前测完成前不能正式提交单元或后测；重测同题不会增加不同题目数。
13. 退出再登录或重启后端，检查草稿、成绩、画像和完成状态仍在。

网络故障检查：先等待草稿保存完成，再在开发者工具启用 Offline 后提交测验。
应显示失败提示，不出现新的成功成绩；恢复网络后可原样重试。
同一提交 ID 和相同答案不会重复计分。多页面冲突时按提示加载最新进度，不静默覆盖。

## 数据和画像规则

课程与单元题库位于 `code/backend/app/domain/content/curriculum.json`，
前测位于 `app/domain/learner/assessment_items.json`。两者由同一个后端目录模块提供，
前端不再打包正确答案或使用本地计分函数。
已有题目版本 1 的内容和选项顺序应保持冻结；变更题库时应同步设计新版本与迁移。

数据位于 `code/backend/local-data/learning.json`；自定义 `OWL_ACCOUNT_FILE` 时，与账号文件同目录。

| 字段 | 含义 |
| --- | --- |
| `submissions` | 所有正式提交：测验/题目 ID、内容及评分版本、所选答案、判分、反馈快照、时间和前测轮次 |
| `state.drafts` | 未提交答案和所在页码，草稿不计入画像 |
| `state.quiz` | 当前前测的服务端结果，普通进度保存无法伪造 |
| `state.checks` / `state.posttests` | 后端从正式提交推导的最近单元/后测记录 |
| `state.completed` | 后端从通过记录推导的单元完成状态 |
| `legacy_progress` | 历史客户端进度归档，不直接作为完成与画像依据 |

画像通过正式作答记录重建，规则版本为 **`first-evidence-v1`**：

- 按来源题目 ID 去重，分数为不同题目的首次记录正确率，不是 HSK 或标准化能力分数。
- 最近一次作答正确率单独显示，反复做同题不增加不同题目数量。
- 后测中复用的题目保留同一来源 ID；新迁移题具有新的来源 ID。
- 每条证据带语言维度、认知目标和知识点标签，聚合成 7 × 6 矩阵。
- 未测评的分数为 `null`；1 题为证据不足，2—4 题为初步证据，5 题以上为证据较多。
  `confidence` 仅为 `min(1, 不同题目数 / 5)` 的数量指标，不是掌握概率。
- 题目标签和阈值属于初始工程规则，尚需教学标注与校准；不以文字选择题推断实际听说、书写、评价或创造能力。
- 尚未采集真实提示等级或开放题评分，未实施架构草案中的支架加权和动态能力公式。

旧版本迁移在内存读取时进行，下次保存时连同归档持久化：

- 已知版本的完整历史前测会重新判分以保留流程，但标记为 `legacy_answers`，不计入新的画像证据。
- 历史未完成前测转换为草稿，保留已选答案与页码。
- 上一轮服务端首单元试点的通过记录保留并纳入画像。
- 其他由旧前端直接生成的完成标记和小测记录归档，需要重新正式提交。

## API

| 方法与路径（前缀 `/api/v1/learning`） | 行为 |
| --- | --- |
| `GET /curriculum` | 公共课程目录和单元内容，不含答案 |
| `GET /quizzes/{quiz_id}` | 取题；已登录时附本人最近结果与草稿 |
| `POST /quizzes/{quiz_id}/submissions` | 已登录用户提交答案，原子更新正式结果与进度 |
| `GET /progress`、`PUT /progress` | 读取进度或保存草稿、方向和页面状态；不能覆盖正式判分和画像 |
| `POST /assessment/reset` | 重开前测，保留历史成果 |
| `GET /profile` | 读取本人的证据画像 |
| `POST /analysis` | 可选的 DeepSeek 前测建议 |

测验 ID：`assessment`、`unit-{topic}-{0..4}`、`post-{topic}`；
`topic` 为 `travel`、`daily`、`campus` 或 `poetry`。
原 `/units/{topic}/{index}/quiz` 与 `/units/{topic}/{index}/submissions` 作为兼容入口保留。

提交体包含 `submission_id`（UUID）、`content_version`、当前 `revision` 和题目 ID / 选择下标。
身份来自会话，不接受目标用户 ID、分数或画像值。
重复 ID 换答案/测验返回 409；过时版本/进度返回 409，非法或缺失答案返回 422，未登录提交返回 401。
前测重开后，上一轮提交 ID 不能恢复为当前前测。

## 自动化验证

后端（在 `code/backend` 下）：

```bash
.venv/bin/python -m pytest -q
```

前端（在 `code/frontend` 下）：

```bash
npm test
npm run build
```

后端测试覆盖所有 25 份测验、全部单元与方向完成、跨用户隔离、并发与幂等、版本冲突、
草稿/重启恢复、旧记录迁移、伪造状态防护和矩阵去重。
一次全题正确的测试流程包含 88 条作答，去重后为 68 道来源题目；20 道复用题不重复计证据。
前端测试覆盖四方向的完整单元和后测交互、草稿恢复、失败重试及后端画像展示。
这些测试使用临时文件或模拟响应，不消耗真实模型额度。

## 页面与交互验收（2026-11-10）

页面按「界面设计、视觉设计、用户体验」三层整理，具体设计与验证范围见
[前端界面设计说明](frontend-design.md)。已有后端判分、草稿、正式成绩和画像规则保持不变。

- 桌面左侧提供学习首页、我的学习、学习方向、学习画像；窄屏改为横向导航。
- 首页优先展示首次设置或继续学习，方向预览、单元进度和学习画像作为次级信息。
- 右上方持续显示游客模式、正在保存、保存成功或尚未保存；失败后保留选择，并提供重试入口。
- 前测和后测增加题号导航，可直接返回未答题。题号边框表示当前题，圆点表示已作答。
- 在 390px 和 1440px 宽度下核对导航、方向选择、测验按钮及画像表格；矩阵可单独横向滚动。
- 使用 Tab 键核对焦点、跳到主要内容链接、题目选项和题号导航。未作答齐全不能提交。
