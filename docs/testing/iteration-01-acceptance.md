## 1. 版本、环境与签收规则

验收前登记：代码提交、题库/评分/提示/计划规则版本、浏览器及视口、运行环境、测试账号代号、执行人和日期。使用隔离PostgreSQL测试数据库、迁移副本与虚构账号，禁止使用真实学习者数据、密码或模型密钥作为fixture。

作者完成自测，分工表中的非作者执行复核。结果使用“未执行/通过/失败/阻塞/不适用”；不适用必须说明范围变更依据，不能用于绕开必验项。失败关联缺陷与复测证据；截图只能证明可见结果，数据幂等和隔离必须补API/存储断言。

每条用例记录字段：`AC编号、关联需求、前置条件、步骤、输入、预期、优先级、实际结果、证据位置、缺陷编号、执行人、复核人、版本、日期`。下表给出前八项的起点；实际结果及签名保持未填写。

## 9. 全局完成门禁

以下全部待本轮执行。课程最低要求取自用户提供的ISWEP课件p.145、164—165；其余为本轮工程验收约定。非功能编号统一取[独立非功能规格](../requirements/nonfunctional_spec.md)。

- [ ] **G-01 功能**：A包6项、B包6项、C包7项、D包6项、E包5项，共30项AC，加UI-A1—UI-E1共5项页面流程，原35项加新增QB-01—QB-09以及AI-C/AI-D/AI-E，共47项均有实际结果、证据和非作者复核；不以开发者口述替代。
- [ ] **G-02 既有回归**：当前51项后端、40项前端测试保持通过；新增测试通过；测试数可因合理重构变化，但原场景覆盖不得丢失；JSON文件专属测试与真实SQL业务测试分开标明，原JSON测试通过不能替代SQL验证。
- [ ] **G-03 静态与构建**：前端lint/类型/构建通过；后端Ruff检查和格式通过。首次完整扫描保存Bug、Code Smell、复杂度和重复率基线。
- [ ] **G-04 重构闭环**：Top 5问题各有负责人、问题影响、先补测试、修改前后证据。若扫描实际不足5个真实问题，如实报告并补人工评审，不制造缺陷。
- [ ] **G-05 覆盖率**：核心逻辑至少60%，前后端分别报告且冻结统计范围；包括本轮判分、诊断、偏好校验、计划、提示和复习规则中未被执行到的文件；行/分支指标分别呈现。课件未指定分支阈值，本轮不虚构其要求。
- [ ] **G-06 CI**：每个PR启动隔离PostgreSQL服务、执行迁移后运行真实SQL集成测试，并执行上述可自动化检查，任一失败使检查失败；测试与覆盖率报告可下载；本机手动通过不替代CI结果。
- [ ] **G-07 真实端到端**：Playwright连接真实前后端和隔离PostgreSQL数据库，跑“注册→偏好→前测→诊断→计划接受→独立提示练习→正式单元提交→报告/复习→退出再登录”。外部LLM可模拟，但账号/判分/存储不得全用前端mock。
- [ ] **G-08 恢复与权限**：覆盖断网重试、后端重启、多标签页冲突、重复请求、跨用户读取/写入；数据不丢失、不串号、不重复计分；失败修复后回归。
- [ ] **G-09 设备和可访问性**：360px与桌面视口实测主要流程、键盘焦点、错误提示；表格允许局部滚动，主操作不得被遮挡；至少一种真实移动设备核对，未做则明确未验证。
- [ ] **G-10 AI与内容**：固定评测集包括全对、全错、单错、同分异错、过时响应与供应商故障；无错误引用/虚构薄弱点；试点轻提示不泄露完整答案；模板来源可识别。
- [ ] **G-11 性能记录**：冻结机器、数据量和负载再测。建议试用基线为预热1分钟、5并发、持续5分钟；普通API P95≤500ms、作答本地处理P95≤800ms；外部LLM单列。它只是本轮小规模基线，不代表生产容量结论。
- [ ] **G-12 流程统计**：固定版本与环境下累计至少20次完整主流程运行，记录分子/分母、故障原因，成功率≥95%；这不是目标用户独立完成率，也不覆盖所有故障概率。
- [ ] **G-13 交叉试用**：至少完成一次与其他小组互测，记录产品价值、功能、体验与建议；若目标用户未招募，不声称满足NFR-8的10—15人/80%独立完成要求，更不声称教学效果提升。
- [ ] **G-14 缺陷闭环**：阻断主流程、越权、数据丢失、错判分、答案违规泄露等高严重度缺陷关闭并复测；其余逐项注明负责人、影响与下一轮安排。

G-07由郑仲佑维护主场景，每人维护本人片段的断言与fixture；G-11由黄云舒汇总API负载与环境，管佳欣只负责数据库连接/查询部分，各负责人定位本包瓶颈；G-09各人检查自己的页面。不得把所有失败修复都转给测试组织者。
