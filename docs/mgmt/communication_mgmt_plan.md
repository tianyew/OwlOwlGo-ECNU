## 1. 沟通目标与当前基线

沟通应使团队成员、课程教师、试用学习者和内容审核者及时获得适合其职责的信息，明确“做什么、谁负责、何时交付、如何验收”，并将讨论转化为可追踪的决定与行动。

截至本次编制，依据[项目入口](../../README.md)、[完整学习链路](../software/server-unit-demo.md)和现有源码，统一采用以下沟通口径：

| 类别 | 当前基线 |
| --- | --- |
| 产品与用户 | 面向成年汉语初学者的 AI 游戏化汉语学习 H5，首批验证场景为来华留学生 |
| 已有学习原型 | Vue 3 + TypeScript 前端、FastAPI 后端；账号与会话；8 题拼音声调前测；旅游出行、日常生活、校园交流、古诗四方向共 20 个单元；每方向 10 题后测；服务端判分和七维 × 六层作答证据画像 |
| 数据与运行 | 登录用户的草稿、正式提交和进度使用 JSON 持久化，已有文件锁、原子替换与 revision 冲突处理；课程和测验依赖后端，不能继续按纯前端离线 mock 说明启动方式 |
| AI 能力 | DeepSeek 可选用于八题前测建议，当前模型 Agent 为 AssessmentAgent；学习搭子界面采用本地规则回复，不调用模型、不修改学习记录 |
| 后续目标 | PostgreSQL、RAG、LangGraph 工作流、动态课程生成与调整、其他辅导 Agent 尚待实现或验证；目标方案与本次演示范围分开说明 |
| 测评边界 | 前测不代表 HSK 等级、听说能力或完整汉语水平；画像空白表示未测评，重复题不增加独立证据；前后测内容不同，不直接计算能力提升百分比 |

本计划沿用[项目计划](project-plan.md)的 17 周阶段安排。该文件仍保留早期进度记录，不能按自然日期推定课程周次或里程碑完成。A 应在首次执行会议中组织核对实际进度，补充证据和新记录。旧演示文档与当前实现不一致时，以当前代码、复现结果和完整学习链路为核对依据，再通过 PR 修正文档。

## 2. 相关方、信息需求与职责

### 2.1 五人团队

沿用 A—E 角色编号，以下为建议分工，实际姓名由团队认领。一人可以协助其他工作，但每项任务必须有一个交付负责人和至少一名非作者复核人。

| 角色 | 主要职责与信息需求 | 交付和沟通责任 | 主要复核关系 |
| --- | --- | --- | --- |
| A：协调与项目管理 | 范围、工作量、依赖、进度、风险和课程要求 | 维护项目计划与管理文档；组织例会；协调阻塞；对接教师；跟踪决策 | B 复核范围与需求，全员评审重大变更 |
| B：测评与教学内容 | 学习者需求、题目质量、拼音及英文辅助、来源许可、画像解释 | 维护题库及验收口径；对接教学审核者；向 C/D 交付版本化内容与评分说明 | E 复核展示与可理解性，专业内容另请具备汉语教学能力者审核 |
| C：前端与用户体验 | API、页面状态、错误处理、移动端与可访问性 | 实现学习交互、进度展示和学习搭子界面；向 D 反馈契约问题；提供复现路径 | D 复核数据一致性，E 复核用户流程 |
| D：后端、AI 与技术质量 | 权限、判分、存储、模型配置、版本、构建和部署 | 维护接口与仓储；验证 AI 边界；汇总技术测试；提供环境、迁移及回退说明 | C 复核接口联调，E 复核验收证据 |
| E：测试协调、汇报与验收 | 验收标准、缺陷、目标用户反馈和展示范围 | 组织交叉测试与彩排；整理 PPT、讲稿、演示及备用材料 | B 复核教学表述，D 复核技术与测试结论 |

A 为关键交付指定替补；E 在展示前确认主讲和备用主讲。D 的工作按后端、AI、部署拆成可认领任务，避免所有关键工作集中于一人。

### 2.2 其他相关方

| 相关方 | 关注的信息 | 组织者与沟通方式 | 反馈闭环 |
| --- | --- | --- | --- |
| 课程教师 | 工程问题、阶段成果、质量证据、进度偏差和待指导问题 | A 统一联系，E 配合课堂汇报；按课程节点提交可访问资料 | A 记录意见并拆为任务，下一次汇报说明处理结果 |

## 4. 渠道、记录与响应规则

### 4.1 信息存放

| 信息 | 权威存放位置 | 使用规则 |
| --- | --- | --- |
| 正式需求、设计与管理计划 | 仓库 `docs/` | 随版本评审，变更说明原因及影响 |
| 任务、缺陷、行动项 | GitHub Issues / Projects | 写明负责人、期限、依赖、验收条件；状态按 Backlog → Ready → In Progress → Review → Done 更新 |
| 代码与文档评审 | GitHub Pull Requests | 关联 Issue；说明修改、原因、验证和限制；至少一名成员评审通过且检查通过后合并 |
| 会议、FAQ、过程讨论 | GitHub Wiki | 会议后 24 小时内整理；影响正式基线的结论另通过 PR 更新 `docs/` |
| 重大技术决定 | `docs/adr/` | 保留背景、备选方案、结论、影响及 Proposed/Accepted 状态 |
| 快速同步 | 团队现用即时通信群，紧急时电话或语音 | 用于提醒和协调，任务与决定补录到 Issue/Wiki |
| 迭代复盘 | `docs/retrospection/` | 记录目标与实际、原因、改进责任人及验证结果 |

首次执行时由 A 核实仓库、Wiki、Projects 和教师访问权限；未配置项进入任务清单。Wiki 暂不可用时，纪要暂附对应 Issue，恢复后迁移并保留链接。本计划不表示平台已经配置完成。

### 4.2 时限与升级

以下为拟执行响应目标。普通事项按团队约定工作日计；发布、演示值守及确认的数据安全事件即时处理，A 安排主备联系人。

| 情况 | 首次响应与处理目标 | 升级路径 |
| --- | --- | --- |
| 一般问题、任务交接、PR 评审请求 | 1 个工作日内确认接收，给出结论或预计完成时间 | 超时由 A 催办并安排替补评审 |
| 接口阻塞、关键任务延期、高风险触发 | 发现即通知责任人与 A；工作时段 2 小时内确认，半天内确定负责人和初步方案 | 阻塞超过半个工作日由 A 协调；影响里程碑时当日召集团队调整 |
| 发布或演示中断、确认的泄露或数据损坏 | 立即通知 D/A/E，值守联系人目标 30 分钟内响应；处置中每小时或有实质进展时同步 | 先停止受影响操作或回退；A 视影响通知教师、受影响用户及相关服务方 |
| 影响课程要求、重大范围或无法解决的外部依赖 | A 当日汇总备选方案、代价和最迟决策时间 | 团队无法解决时，在下一检查节点前向教师寻求指导，不等截止日 |

发起者提供版本、复现步骤、影响范围、已尝试措施和所需帮助。接收者明确“已接收、负责人、下一次更新时间”；未回复不等于同意。风险等级与紧急程度见[风险管理计划](risk_mgmt_plan.md)。

## 5. 决策、变更与会议闭环

1. **会前准备：** A 提前 1 个工作日发送议题、材料和待决问题，紧急事项可临时召开；各负责人更新任务、测试证据和风险状态。
2. **会议议程：** 核对上次行动项、本周成果与偏差，处理接口及外部依赖，重评风险，确认下周交付。一般实现细节由责任人与评审人处理，跨模块问题进入例会。
3. **重大决策：** 范围、架构、数据库迁移、AI 数据边界和发布条件由五人共同评审，逐一记录同意、有条件同意或异议及理由。未达成一致时保留待决状态，列出补充验证与期限，必要时请教师协调。
4. **变更控制：** 新需求先提交 Issue，说明收益、FR/NFR、工作量、依赖、进度与成本影响、替代或延期项及风险。评审后同步 Backlog、设计和验收标准，不能只改代码。
5. **展示冻结：** 展示前 2 天冻结功能与讲稿范围。阻塞缺陷修复后必须回归；其他变更重新评估彩排和回退成本。历史 mock 演示若作为备用材料，须明确版本及能力边界。
6. **会后闭环：** A 在 24 小时内发布纪要，行动项均有负责人、截止和验收证据，相关成员在 1 个工作日内核对。技术结论落 ADR，正式需求落文档，遗留问题进入下次检查。

## 6. 验收沟通与信息保护

- E 组织非实现者按[完整学习链路](../software/server-unit-demo.md)复现，记录版本、环境、步骤、预期与实际结果；已有测试文件不代表本次测试已经通过。
- D 提供后端 `python -m pytest`、前端 `npm test` 和 `npm run build` 等适用检查结果。当前 CI 主要检查目录、前端构建与 Python 语法，不能将 CI 通过表述为全部业务测试通过；跨系统测试与 AI 评测仍需补齐。
- 演示同时启动前后端。DeepSeek 不可用时仍演示规则判分、课程和画像，并说明 AI 建议暂不可用；学习搭子的本地回复单独说明。公开发布另按非功能需求验收，不能用原型展示替代发布质量门。
- 面向教师说明工程结果、证据和限制；面向学习者说明操作与下一步；面向技术成员提供契约、版本和复现资料，避免信息粒度不匹配。
- 不在仓库、群聊、会议截图、PPT 或公开 Issue 传播密钥、会话令牌、真实账号文件或可识别学习记录。测试材料使用合成或去标识化数据，对外分享遵循最小必要范围。

## 7. 记录模板与计划检查

**会议纪要：** 日期与时区 / 参会人 / 议题 / 证据链接及版本 / 各方意见 / 决策与理由 / 行动项（负责人、截止、验收条件）/ 遗留问题 / 下次检查时间。

**周报：** 本周目标 / 实际交付与证据 / 计划偏差 / 阻塞及风险 ID / 需要的支持 / 下周计划 / 负责人和期限。

**交接记录：** 关联 Issue / 交付版本 / 输入输出或接口示例 / 验收步骤 / 已知限制 / 接收人确认 / 后续问题。

每周 A 检查关键任务是否均有负责人、期限和验收条件，会议行动项是否按时关闭，是否存在超过 1 个工作日无人响应的请求，以及代码、文档、PPT 与实际状态是否一致。发现遗漏在当次例会纠正，阶段复盘时调整沟通频度和角色负荷。以上时限与指标均为管理目标，不表示已达成。

首次执行会议需落实：五人姓名及替补、固定会议时间、当前里程碑与展示日期、外部审核者和试用联系人、平台权限、模型与部署预算责任人。
