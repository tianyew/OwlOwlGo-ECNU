# 沟通管理计划

更新：2026-11-02。适用于下周原型展示准备及后续迭代。本文为团队执行草案；角色分配、展示日期和技术方案须由 5 人共同确认，未记录为已经通过。

## 本轮共同目标

用固定演示数据和真实交互跑通：前测 → 诊断 → 兴趣选择 → 预设学习规划。诊断按实际作答计算，计划按主题读取；真实 RAG、模型生成、正式能力测评和动态学习调整不作为本轮验收条件。

## 五人职责与交接

成员姓名由首次例会填写；一人可协助其他任务，交付责任保持明确。

| 角色 | 主要交付 | 交接与复核 |
| --- | --- | --- |
| A 协调与管理 | 范围、任务清单、两份管理文档、会议纪要 | B 复核；汇总全体意见 |
| B 测评与内容 | 题目、诊断文案、主题计划和单元说明 | C 复核语言与展示口径 |
| C 前端交互 | 四模块页面、状态传递、mock 接口 | D 复核流程和数据一致性 |
| D 技术与质量 | 架构评审材料、构建测试、演示环境 | C 复核复现步骤 |
| E 汇报与验收 | PPT、5 分钟讲稿、演示与备用录屏 | 全员预演；E 暂定主讲，待确认 |

## 渠道与节奏

| 场景 | 渠道 | 频率与时限 | 输出 |
| --- | --- | --- | --- |
| 日常同步 | 项目群 | 准备期每天一次，说明完成项、下一步与阻塞；原则上 24 小时内回应 | 关键事项转入 Issue |
| 任务和缺陷 | GitHub Issues / Projects | 发现时记录，负责人每日更新 | 负责人、验收条件、优先级、证据 |
| 代码与正式文档 | 分支 + PR | 每项交付发起评审，由另一成员复核 | 修改说明、检查结果与评审记录 |
| 范围与技术评审 | 5 人会议 + Wiki 纪要 | 开始前一次，展示前至少一次 | 每人意见、结论、遗留问题、负责人 |
| 架构决策 | docs/adr | 技术选择变更时 | Proposed / Accepted 状态及依据 |
| 演示彩排 | 共享屏幕或线下 | 展示前 1 天，计时 5 分钟 | 缺陷清单、备用方案、主讲确认 |

上述外部任务、会议及录屏需要团队实际执行；本文不代表已创建 Issue、发送通知或完成会议。

## 决策和变更

1. A 在评审前发出范围、架构和待决问题；5 人分别记录“同意 / 有条件同意 / 有异议”及理由。未回复不算同意。
2. 本轮先确认 Vue 前端和本地 Promise mock 的可运行性；FastAPI、数据库、RAG 和模型属于后续实现，分别记录可行性与待验证条件。
3. 有异议的方案保留为待评审；A 组织讨论，不能达成一致时记录备选与影响，必要时请课程教师协调。
4. 展示前 2 天冻结演示范围。新增功能须说明收益、工作量与替代项，经团队确认后调整；阻塞演示的缺陷优先修复。
5. 阻塞超过半天由责任人向 A 提出，附复现步骤、影响及回退建议；A 当日协调，不等下次例会。

## 会议记录模板

日期 / 参会人 / 议题 / 证据链接 / 5 人逐一意见 / 决策及理由 / 待办负责人和期限 / 下次检查时间。

## 展示验收与信息一致性

- 全员核对 [演示验收说明](../software/demo-guide.md)，由非实现者按步骤复现。
- E 负责 3 分钟原型演示 + 2 分钟技术架构；PPT、页面和口头表述统一说明演示数据及测评限制。
- A 汇总证据后再更新项目计划实际完成项；不得按自然日期推定课程里程碑完成。
- 正式资料存仓库，讨论纪要存 Wiki；不在群聊或仓库传播密钥及真实学习者敏感数据。
