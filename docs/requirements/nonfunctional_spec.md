# OwlOWLGo：软件系统非功能需求规格说明书

## 0. 文档信息

| 项目 | 内容 |
| --- | --- |
| 系统名称 | OwlOWLGo AI 游戏化英语学习伙伴 |
| 文档名称 | 软件系统非功能需求规格说明书 |
| 版本 | v1.1 草案 |
| 更新日期 | 2026-10-09 |
| 适用范围 | 大学生英语词汇、语法和短篇阅读学习 MVP |
| 编号规则 | `NFR-x` 表示一条可验证的非功能需求 |

## 1. 目的与适用范围

本文定义 OwlOWLGo MVP 在性能、可靠性、可用性、安全与隐私、兼容性、可维护性、可观测性、可追溯性以及 AI 质量方面必须满足的约束。除明确标为后续目标的条目外，Must 条目均为 MVP 发布门槛。

## 2. 非功能需求

| 编号 | 类别 | 需求描述 | 验证方法 | 优先级 |
| --- | --- | --- | --- | --- |
| NFR-1 | 性能 | 普通业务 API 在约定测试环境和正常负载下 P95 响应时间不超过 500 ms，不含外部 LLM 调用 | 接口压测报告 | Must |
| NFR-2 | 性能 | 作答提交的本地判定、持久化和策略决策 P95 不超过 800 ms；需调用 LLM 时先返回可感知的处理中状态 | 端到端计时与追踪 | Must |
| NFR-3 | 性能 | H5 首屏在稳定校园网络下 3 秒内达到可交互状态，压缩资源不重复下载 | Lighthouse 与真机测试 | Should |
| NFR-4 | 可靠性 | 核心学习流程成功率不低于 95%，单次外部 AI 故障不得导致会话数据丢失 | 故障注入与流程统计 | Must |
| NFR-5 | 可靠性 | 作答、知识状态和奖励更新应具备幂等性，重复请求不得重复计分 | 重放测试 | Must |
| NFR-6 | 可靠性 | 学习中断后可恢复到最近一个已确认步骤；已提交作答不可静默丢失 | 浏览器关闭和网络中断测试 | Must |
| NFR-7 | 可靠性 | LLM 超时、不可用或校验失败时，系统必须回退到题库解析或模板反馈 | 模拟超时、错误响应和断网 | Must |
| NFR-8 | 可用性 | 不少于 80% 的目标测试用户无需现场指导即可完成初始测评和一个学习关卡 | 10–15 人可用性测试 | Must |
| NFR-9 | 可用性 | 关键错误信息说明发生了什么及可采取的下一步，不直接展示堆栈或内部异常 | UI 走查和错误场景测试 | Must |
| NFR-10 | 可访问性 | 键盘可访问主要学习流程；表单有标签；文本与背景达到 WCAG 2.1 AA 常规文本对比度 | 自动检查与人工键盘测试 | Should |
| NFR-11 | 安全性 | 密码使用成熟密码哈希方案，系统不保存或记录明文密码 | 代码审查与数据库检查 | Must |
| NFR-12 | 安全性 | API Key、Token 和数据库凭据仅由环境或 Secret 服务注入，不进入仓库和普通日志 | Secret 扫描与日志审查 | Must |
| NFR-13 | 安全性 | 所有受保护资源执行服务端身份与对象级权限校验；普通用户不可访问他人会话或报告 | 越权测试 | Must |
| NFR-14 | 安全性 | 输入执行长度、类型和格式校验；富文本输出进行转义或净化，防止常见注入与 XSS | 安全测试 | Must |
| NFR-15 | 隐私 | 只收集实现学习功能和评估所需的最少数据；研究数据使用随机标识替代直接身份信息 | 数据字段评审 | Must |
| NFR-16 | 隐私 | 用户可以查看主要数据类别并提交删除申请；删除过程和结果可审计 | 功能与数据库验证 | Must |
| NFR-17 | 隐私 | 未成年人不属于 MVP 招募对象；研究测试前提供用途、范围和退出方式说明 | 招募材料审查 | Must |
| NFR-18 | 兼容性 | 支持当前主流 Chromium 浏览器最近两个稳定版本，并完成一种移动端和一种桌面端尺寸测试 | 浏览器矩阵测试 | Must |
| NFR-19 | 兼容性 | 核心页面在 360 px 宽度下不出现阻挡主要操作的横向溢出 | 响应式测试 | Must |
| NFR-20 | 可维护性 | 学习领域规则不依赖 Web 框架；策略、LLM 适配、提示模板和持久化实现彼此解耦 | 架构和依赖审查 | Must |
| NFR-21 | 可维护性 | 核心领域规则具备单元测试，关键学习闭环具备集成或端到端测试 | 测试报告 | Must |
| NFR-22 | 可维护性 | 需求、代码和测试通过 FR/NFR 编号、Issue 或 PR 建立追踪关系 | 抽样追踪审计 | Should |
| NFR-23 | 可观测性 | 记录请求 ID、会话 ID、策略版本、延迟、降级原因和错误类型，不记录密码或完整密钥 | 日志检查 | Must |
| NFR-24 | 可观测性 | 可统计核心流程成功率、API P95、LLM 超时率、校验失败率和降级率 | 指标查询或报告 | Should |
| NFR-25 | 可追溯性 | 100% 任务推荐和干预决策保存输入快照、动作、原因、置信度和策略版本 | 数据完整性检查 | Must |
| NFR-26 | 可追溯性 | AI 候选内容保存生成约束、模型标识、校验结果、审核状态和版本 | 内容审计测试 | Should |
| NFR-27 | AI 质量 | 所有 AI 输出先通过结构校验、答案一致性、难度/词表、提示泄露和敏感内容检查后再展示或入库 | 固定 AI 评测集 | Must |
| NFR-28 | AI 质量 | 2 级轻提示的完整答案泄露率目标为 0；发现泄露时阻断展示并降级 | 提示泄露测试集 | Must |
| NFR-29 | AI 质量 | AI 生成题不得自动进入正式题库，必须通过人工审核 | 权限与状态流测试 | Must |
| NFR-30 | AI 质量 | 模型供应商可通过适配器替换，核心领域和 API 不直接依赖供应商 SDK 类型 | 架构依赖测试 | Should |

## 3. 运行与测试基线

| 项目 | MVP 基线 |
| --- | --- |
| 后端运行时 | Python 3.12、FastAPI |
| 前端运行时 | Node.js 22、Vue 3、TypeScript、Vite |
| 数据库 | PostgreSQL 17 |
| 参考负载 | 小规模课程试用；正式并发目标在原型测量后确定 |
| 性能统计 | 预热后统计 P50、P95、P99，外部 LLM 延迟单列 |
| 测试数据 | 合成或去标识化数据，不使用真实密码与密钥 |
| 发布环境 | HTTPS；开发、测试与生产配置分离 |

## 4. 发布质量门

MVP 发布前必须同时满足：

1. Must 功能验收通过，核心学习流程成功率不低于 95%；
2. 不存在已知的严重越权、明文密钥、明文密码或真实用户数据泄露；
3. 普通 API P95 满足 NFR-1，LLM 延迟和失败率能够单独观察；
4. LLM 故障降级、重复提交幂等、会话恢复和数据删除场景通过测试；
5. AI 评测集中不存在未被阻断的完整答案泄露和已知错误答案；
6. 功能规格、非功能规格、测试结果和实际实现保持一致。

## 5. 非功能验收矩阵

| 验收活动 | 覆盖需求 |
| --- | --- |
| API/端到端性能测试 | NFR-1～NFR-3 |
| 故障注入、重放和恢复测试 | NFR-4～NFR-7 |
| 目标用户可用性测试 | NFR-8～NFR-10 |
| 身份、越权、输入与 Secret 检查 | NFR-11～NFR-14 |
| 数据字段、导出与删除检查 | NFR-15～NFR-17 |
| 浏览器和响应式测试 | NFR-18～NFR-19 |
| 架构、测试和需求追踪审查 | NFR-20～NFR-22 |
| 日志、指标和决策记录检查 | NFR-23～NFR-26 |
| AI 固定评测集与人工审核流程 | NFR-27～NFR-30 |

## 6. 待确认项

- 正式并发用户数和服务器规格需在 MVP 原型测量后确定；
- LLM 响应时间目标需结合供应商、预算和流式输出方式确定；
- 备份恢复点目标（RPO）和恢复时间目标（RTO）需在部署方案确认时补充；
- 数据保留期限需结合课程研究方案和知情说明确定；
- 正式实验样本量需经过功效分析，不由本非功能规格直接承诺。
