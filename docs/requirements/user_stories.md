# OwlOWLGo 用户故事清单

> 版本：v1.0 草案  
> 更新日期：2026-10-15  
> 目标用户：18 岁及以上、以汉语作为第二语言或外语学习的大学生  
> 对应范围：汉语词汇、语法和短篇阅读 MVP

## 1. 编写与验收约定

用户故事采用“作为……我希望……以便……”格式。验收条件使用 Given–When–Then，并覆盖正常流程、异常流程和关键质量约束。优先级采用 MoSCoW：Must 为核心学习闭环，Should 为重要增强，Could 为时间允许时实现。

“独立”表示故事可以单独讨论、估算和验收，不表示实现时不存在业务依赖。涉及 AI 的故事必须具有不依赖外部模型的降级路径。

## 3. 详细用户故事

### US-01 设置汉语学习目标与提示偏好

**故事**：作为一名非汉语母语学习者，我希望设置当前汉语水平、学习目标、每日可用时间和主动提示偏好，以便系统安排适合我的学习任务且尊重我的帮助偏好。

**价值**：为冷启动推荐和干预策略提供最少必要信息。  
**优先级**：Must  
**规模建议**：3 Story Points

**验收条件**：

1. **保存有效档案**
   - Given 学习者已进入目标设置页
   - When 选择当前水平、学习目标、每日时间和提示偏好并提交
   - Then 系统保存档案并进入测评入口
   - And 再次进入该页面时显示最近一次保存的选择
2. **阻止无效输入**
   - Given 必填项未填写或每日时间超出允许范围
   - When 学习者提交
   - Then 页面指出具体问题且不丢失已经填写的内容
3. **关闭主动提示**
   - Given 学习者关闭主动提示
   - When 后续进入学习关卡
   - Then 系统不展示未经请求的教学提示
   - And 主动求助与必要的答题结果反馈仍然可用
4. **隐私最小化**
   - Given 学习者设置学习档案
   - When 系统保存数据
   - Then 不要求与核心学习功能无关的敏感信息

### US-02 完成初始汉语能力测评

**故事**：作为首次使用系统的学习者，我希望在 10 分钟内完成包含词汇、语法和短篇阅读的初始测评，以便系统得到我的能力起点并推荐合适任务。

**价值**：降低推荐和干预的冷启动偏差。  
**优先级**：Must  
**规模建议**：5 Story Points

**验收条件**：

1. **完成测评**
   - Given 学习者已设置学习目标
   - When 完成全部测评题并提交
   - Then 系统展示词汇、语法和阅读分项结果
   - And 初始化相关知识点的掌握状态与置信度
2. **记录过程**
   - Given 学习者正在测评
   - When 提交任意一道题
   - Then 系统记录题目、答案、正误、耗时、尝试序号和时间戳
3. **中断恢复**
   - Given 学习者至少完成一道题
   - When 页面刷新或会话中断后重新进入
   - Then 从最近一个已确认步骤继续
   - And 已确认答案不会被重复提交
4. **时间与可用性**
   - Given 目标用户参加可用性测试
   - When 独立完成测评
   - Then 目标完成时间不超过 10 分钟
   - And 主要操作可通过键盘完成

### US-03 获得可解释的个性化任务

**故事**：作为完成初始测评的学习者，我希望系统根据我的知识缺口、任务难度和复习需要推荐下一项汉语任务，以便练习既有挑战又不会难到无法开始。

**价值**：让任务选择与个人状态相关，而不是固定题序。  
**优先级**：Must  
**规模建议**：5 Story Points

**验收条件**：

1. **选择合格任务**
   - Given 候选题中存在已启用且审核通过的内容
   - When 系统生成下一项任务
   - Then 只从元数据完整、已启用、已审核的题目中选择
2. **保存推荐依据**
   - Given 系统推荐了一项任务
   - When 推荐完成
   - Then 保存输入快照、题目 ID、推荐原因、置信度和策略版本
3. **面向学习者解释**
   - Given 学习者查看推荐任务
   - When 展开“为什么推荐”
   - Then 显示简短的非技术化原因
   - And 原因与保存的决策记录一致
4. **冷启动降级**
   - Given 学习者历史数据不足
   - When 系统选择任务
   - Then 使用保守默认策略
   - And 不因缺少历史数据阻塞学习

### US-04 提交答案并可靠记录学习过程

**故事**：作为正在练习的学习者，我希望提交汉语题目答案后立即看到判定并保存进度，以便网络波动或重复点击不会让我丢失记录或被重复计分。

**价值**：建立可信、可恢复的核心学习链路。  
**优先级**：Must  
**规模建议**：8 Story Points

**验收条件**：

1. **正常提交**
   - Given 学习者处于有效会话且当前题目允许作答
   - When 提交符合格式的答案
   - Then 系统返回判定结果、干预动作和知识状态摘要
   - And 保存作答及关联学习事件
2. **幂等提交**
   - Given 同一作答请求已经成功处理
   - When 客户端使用相同幂等键再次提交
   - Then 返回与首次处理一致的结果
   - And 不重复更新知识状态、经验值、成就或连续学习记录
3. **权限与状态校验**
   - Given 会话不属于当前用户、已完成或已经失效
   - When 用户提交答案
   - Then 服务端拒绝操作并返回可理解的错误
   - And 不写入作答或奖励记录
4. **处理中反馈**
   - Given 后续提示需要调用外部 LLM
   - When 本地判题、状态更新和干预决策已完成
   - Then 在 800 ms 性能目标内返回确定性结果或明确的处理中状态
   - And 外部调用不长时间占用核心数据库事务

### US-05 在合适时机获得渐进式帮助

**故事**：作为遇到困难的汉语学习者，我希望系统根据错误次数、作答时间和求助行为逐步提供帮助，以便我保留独立思考机会，又不会长时间无效挣扎。

**价值**：这是 OwlOWLGo 区别于普通题库和直接给答案式 AI 的核心能力。  
**优先级**：Must  
**规模建议**：8 Story Points

**验收条件**：

1. **首次错误不直接揭晓答案**
   - Given 学习者第一次提交错误答案
   - When 系统完成干预决策
   - Then 默认返回 0～2 级动作
   - And 不展示完整答案
2. **逐级增加支架**
   - Given 学习者连续答错、明显超出个人耗时基线或反复无效修改
   - When 策略重新评估学习状态
   - Then 可以从鼓励再试升级为轻提示、分步支架或完整讲解
   - And 不出现无限无帮助循环
3. **主动求助**
   - Given 学习者主动点击“给我一点提示”
   - When 系统读取已经使用的提示级别
   - Then 返回下一适当级别的帮助
   - And 学习者可以明确请求完整讲解
4. **防止提示泄露**
   - Given 策略选择 2 级轻提示
   - When AI 或模板生成候选提示
   - Then 完整答案泄露检查必须通过后才能展示
   - And 检查失败时阻断候选内容并降级
5. **外部服务失败**
   - Given LLM 超时、不可用或输出未通过校验
   - When 系统需要返回帮助
   - Then 使用题库解析或模板反馈
   - And 学习会话及已提交答案不丢失
6. **决策可追踪**
   - Given 任意一次 0～4 级干预决策
   - When 决策完成
   - Then 保存输入快照、动作、原因、置信度和策略版本

### US-06 讲解后完成迁移练习

**故事**：作为已经查看完整讲解的学习者，我希望完成一道考查相同知识点但情境不同的题目，以便确认自己理解了规则而不是只记住原题答案。

**价值**：将即时纠错延伸为可观测的迁移学习。  
**优先级**：Must  
**规模建议**：3 Story Points

**验收条件**：

1. Given 学习者查看了 4 级完整讲解  
   When 系统安排后续任务  
   Then 至少安排一道与原题共享目标知识点的迁移题  
   And 迁移题的表述、例句或情境与原题不同
2. Given 没有可用的 AI 迁移题或生成校验失败  
   When 系统选择迁移练习  
   Then 使用题库中已审核的同知识点题目  
   And 不展示未经审核的生成题
3. Given 学习者完成迁移题  
   When 系统生成报告  
   Then 将迁移题结果与原题和干预记录关联

### US-07 查看学习进展与决策原因

**故事**：作为持续学习汉语的学习者，我希望查看知识点变化、常见错误、提示依赖和下一步建议，以便理解自己的进步以及系统为什么提供某些帮助。

**价值**：增强学习反思和系统可解释性。  
**优先级**：Should  
**规模建议**：5 Story Points

**验收条件**：

1. Given 学习者至少完成一个关卡  
   When 打开学习报告  
   Then 显示完成情况、知识点掌握变化、常见错误、提示依赖和下一步建议
2. Given 报告包含推荐或干预记录  
   When 学习者查看原因  
   Then 显示非技术化说明且与保存记录一致
3. Given 普通学习者请求其他用户的报告  
   When 服务端校验对象权限  
   Then 拒绝访问且不泄露对方数据是否存在
4. Given 页面宽度为 360 px  
   When 查看报告主要内容  
   Then 不出现阻挡主要操作的横向溢出

### US-08 审核 AI 候选学习内容

**故事**：作为内容管理员，我希望查看 AI 候选题的生成约束、答案、解析和校验结果，并决定批准、修改或驳回，以便未经验证的内容不会进入正式学习流程。

**价值**：降低生成内容错误、超纲和提示泄露风险。  
**优先级**：Could  
**规模建议**：8 Story Points

**验收条件**：

1. Given AI 已生成候选题  
   When 管理员打开审核页  
   Then 显示知识点、题型、难度、模型标识、答案、解析和全部校验结果
2. Given 候选题未通过机器校验或人工审核  
   When 普通学习会话请求下一题  
   Then 该题不会进入候选集合
3. Given 管理员批准候选题  
   When 审核状态保存成功  
   Then 记录管理员、时间、版本和审核结果
4. Given 已被作答记录引用的正式题目  
   When 管理员停用内容  
   Then 题目不再进入新会话
   And 历史记录仍可追踪
