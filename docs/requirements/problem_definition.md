# OwlOwlGo：汉语学习网页产品定义

> 版本：v2.0 · 更新日期：2026-10-15 · 产品转向基线

## 1. 产品定位与核心价值

OwlOwlGo（中文之旅）是面向成年汉语初学者的响应式学习网页，结合汉语语言训练、生活情境与文化解释，通过渐进提示帮助学习者独立完成练习。核心价值是“学会一句能用的中文，理解它背后的文化”。前端采用 Vue 3 + TypeScript，后端规划采用 FastAPI；无需原生 App 安装。

保留原项目可解释的任务推荐、五级干预和游戏化方向，新增声调、汉字及文化内容维度。语言训练与文化体验共同组成课程，而文化知识不替代语言能力训练。

## 2. 目标用户与边界

| 人群 | 需求与场景 | 优先级 |
| --- | --- | --- |
| 18 岁及以上、零基础或初级的来华留学生 | 校园问候、点餐、交通、日常沟通；英语辅助和拼音支持 | 首批核心用户 |
| 成年海外汉语初学者及文化兴趣者 | 碎片化学习、读懂常见汉字、理解生活文化 | 首批辅助验证 |
| 成年海外华裔学习者 | 听说与识字能力不均衡，需要独立识字路径 | 后续分层扩展 |
| 商务人士 | 会议、邮件、行业表达与职场礼貌 | 后续专题课程 |

MVP 使用简体中文、普通话拼音和英文释义。繁体、更多辅助语言、儿童课程、专业商务内容以及原生 App 不进入首轮范围。不将海外华裔或商务人士的学习需求视为与零基础用户相同。

## 3. 5W1H 工程问题

| 维度 | 定义 |
| --- | --- |
| What | 如何将声调、字形、词义和生活情境组织为可完成的小课，并在用户卡住时逐步提示？ |
| Why | 降低初学者面对陌生文字和发音体系的入门负担，帮助把练习迁移到实际沟通。 |
| Who | 以成年初级汉语学习者为主；内容审核者负责语言、拼音与文化说明质量。 |
| Where | 手机和桌面浏览器中的独立练习、复习与文化阅读。 |
| When | 首次学习、答错重试、主动求助、间隔复习时。 |
| How | 精选内容起步；策略与生成分离；通过独立完成率、同类错题复发率、迁移题及延迟测验验证。 |

## 4. 五个产品方向及验证方法

下列机会来自选题建议，是本项目选择汉语方向的假设，不是已完成的市场调研结论。不据此断言英语产品没有文化价值、汉语竞品稀缺或市场必然增长。

| 方向 | 产品落实 | 需要验证 |
| --- | --- | --- |
| 需求缺口 | 聚焦初到中国的初学者，围绕校园和生活沟通 | 访谈现有工具的不足，比较真实竞品任务完成体验 |
| 语言与文化 | 每课关联用法、文化语境与适用边界 | 用户是否愿意阅读文化卡，是否提升表达恰当性 |
| 用户空间 | 分阶段验证留学生、文化兴趣者、华裔与商务人群 | 各群体招募渠道、留存、需求强度和获客成本 |
| 技术复用 | 复用 Vue/FastAPI、推荐、提示和游戏化架构 | 声调与字形数据适配成本；语音在不同设备的支持度 |
| 汉语差异化 | 声调与变调、形近/同音字、量词、笔顺及情境表达 | 专项训练能否减少对应错误；是否优于通用选择题 |

## 5. 内容资产与差异化

内容资产按“知识点—词语—情境任务—文化卡—复习任务”关联，每项正式内容记录 ID、版本、来源、使用许可、编写者、审核者、审核状态和更新日期。原创内容也应说明作者和审核状态，示例内容不能自动视作正式审核题库。

汉语内容字段：简体字、带调拼音、音节和声调、语流变调说明、英文释义、例句、量词/语法标签、形近字与同音字、文化主题、关联任务。笔顺与音频须单独记录资源来源和授权，避免未经许可复制字库或课程。

竞争优势需要持续积累的准确内容、错误路径与复习数据来支撑。文化主题本身不构成不可复制的壁垒。书法、成语、历史作为分级扩展内容，首版不向零基础用户集中推送高难度成语。

## 6. 当前实现与 MVP 路线

| 阶段 | 范围 | 状态 |
| --- | --- | --- |
| 当前架构阶段 | 产品定义、页面与功能清单、前后端模块目录、数据/API 草案、静态项目入口 | 已完成架构骨架，业务待实现 |
| 核心 MVP | 分维度初始测评、账户和服务端进度、知识点级推荐、五级干预、错题与间隔复习、报告 | 待实现 |
| 汉语专项 | 人工审核的声调音频、声调听辨、基础笔顺动画与描摹；量词和同音字辨析 | 待实现 |
| 后续增强 | 经验证的语音评分、书写识别、受约束 AI 反馈、多语支持 | 待验证与实现 |

后续若使用浏览器语音，只能作为辅助听读，不能当作标准录音或发音测评。课程完成进度与掌握度测量应分开设计。当前入口不播放语音、不保存学习记录。

## 7. 商业空间

免费提供入门课程；在验证留存后探索个人订阅（专题路径、复习与学习报告）、文化主题课程包，以及高校国际教育项目合作。商务课程可在需求验证后作为独立方向。当前无支付功能、不设未经验证的定价、不宣称已取得收入或机构合作。

验证顺序：5–10 名目标用户访谈 → 10–15 名用户可用性测试 → 小规模持续使用与付费意愿访谈。跟踪入门小课完成率、次周留存、复习完成率、真实情境迁移、内容制作成本和每活跃用户服务成本。用户规模及市场增长待外部资料和实际招募验证。

## 8. 验收与风险

当前架构验收：汉语产品定位一致；模块职责明确；页面、数据与接口设计可供后续开发；静态入口可构建；后端语法通过。具体功能验收在开发阶段执行。

后续 MVP 验收：≥80% 测试用户能独立完成测评和一个关卡；每次策略决策可追踪；汉字、拼音、答案和文化内容经过审核。学习效果需通过实验验证，不将原型完成率解释为教育效果。

主要风险：声调评分难度、字形资源许可、文化概括失真、初学者界面语言负担、前期内容生产成本。分别通过分阶段落地、授权资源、人工审核、英文辅助和有限主题试点控制。
