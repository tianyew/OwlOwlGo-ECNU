# OwlOwlGo 工程问题定义：5W1H 与产品描述

> 文档版本：v1.0  
> 更新日期：2026-10-08  
> 文档状态：第一周问题定义基线  
> 输入依据：工作区 `requirements.md`、`solution-design.md` 及课程提供的 5W1H/产品描述模板

## 1. 执行摘要

OwlOwlGo 要解决的不是“如何再做一个英语题库或聊天机器人”，而是一个可观察、可计算、可验证的学习调控问题：**当大学生进行英语练习时，系统如何根据其知识状态和实时作答过程，判断是否需要介入、何时介入以及提供多少帮助，从而避免过早给答案和长时间无效挣扎，并促进独立思考、纠错与迁移？**

产品形态为面向桌面端与移动端浏览器的 H5 游戏化英语学习应用。MVP 聚焦词汇、语法和短篇阅读，以精选题库为主、受约束的 AI 生成内容为辅，不进行大模型微调。关键的任务推荐和干预决策由可测试、可解释的策略模块完成，LLM 主要负责生成符合既定干预级别的自然语言提示与讲解。

## 2. 工程问题陈述

### 2.1 一句话问题定义

面向有英语学习需求的大学生，设计并实现一个能够持续估计学习状态、动态匹配任务难度，并在适当时机选择“不介入—再试—轻提示—分步提示—完整讲解”的 H5 学习系统，使帮助既不过早替代思考，也不过晚造成无效挫败，同时保证决策可解释、过程可回放、效果可评估。

### 2.2 问题边界

| 维度 | 本项目范围 | 本阶段不解决 |
| --- | --- | --- |
| 用户 | 18 岁及以上、有英语提升需求的大学生 | 中小学生、教师教学管理端、企业培训用户 |
| 内容 | 通用大学英语词汇、语法、短篇阅读 | 多学科课程、完整考试培训体系、开放作业代答 |
| 终端 | 响应式 H5 网页 | 原生 iOS/Android、小程序 |
| AI 决策 | 学习状态估计、任务推荐、五级干预 | 让 LLM 独立决定掌握度、分数、权限或高风险策略 |
| AI 生成 | 受约束的提示、讲解、迁移题和候选内容 | 未经校验直接入库或展示的自由生成内容 |
| 模型 | 首版采用规则与可解释评分，后续比较轻量模型 | 大模型微调、缺少数据支撑的复杂神经策略 |
| 研究 | 小规模校内可用性和学习效果评估 | 在没有足够样本时宣称普遍或显著的教育效果 |

## 3. 5W1H 分析

| 维度 | 核心回答 | 工程化定义与边界 |
| --- | --- | --- |
| **What：什么问题** | 现有 AI 学习工具常在用户提问或答错后直接给出答案；传统游戏化产品通常只按正误调整难度。两者都缺少对“是否介入、何时介入、介入多少”的动态判断。 | 系统需要采集正确性、耗时、尝试次数、求助行为和历史掌握度，形成可计算的学习状态，并输出任务选择与 0–4 级干预动作。核心瓶颈是学习状态不完全可见、干预时机难以判断以及策略效果缺少可回放数据。 |
| **Why：为什么要解决** | 过早帮助会缩短检索、推理、自我解释和纠错过程，使学习者形成提示依赖；过晚帮助会造成无效挣扎和挫败。单纯追求做题量、即时正确率或停留时间，不能代表深层学习。 | 需要在独立尝试和及时支架之间建立可验证的平衡，并通过迁移题、延迟测验、提示依赖和任务完成率评价效果。现有通用聊天 AI 缺少稳定的学习过程状态，传统题库又缺少主动干预策略。 |
| **Who：谁受影响** | 主要用户是需要提升英语词汇、语法和阅读能力的大学生，尤其是希望碎片化学习、但容易依赖答案或因连续失败放弃的学习者。授课教师、课程团队和研究分析人员是次要利益相关者。 | MVP 招募范围限定为 18 岁及以上大学生。初始验证计划招募 **30–50 人**进行可用性和小规模对照测试；这是项目招募目标，不是现有用户数或市场规模。 |
| **Where：在哪里发生** | 问题主要发生在用户独立使用网页完成测评、关卡练习、错误纠正和复习的运行阶段，尤其发生在“提交答案—等待反馈—再次尝试”的交互节点。 | 系统运行于桌面端和移动端主流浏览器。关键工程位置是 H5 学习界面、学习会话服务、学习者模型、干预策略引擎、LLM 适配层和学习事件数据库。 |
| **When：何时发生** | 当用户首次答错、连续答错、明显超出个人基线耗时、反复无效修改、主动求助，或表现出较高提示依赖时，需要重新判断干预。正常持续思考时也需要作出“暂不介入”的明确决策。 | 触发条件必须配置化。基线规则包括：首次错误优先鼓励再试；连续错误或耗时超过个人基线时逐级增加支架；连续失败达到上限或明确请求讲解时给出完整解释；LLM 超时或校验失败时回退到题库解析和模板反馈。 |
| **How：如何衡量** | 不能只用即时正确率评价。应同时衡量可用性、稳定性、学习迁移、干预适当性、参与度、AI 可靠性与隐私安全。 | MVP 目标包括：≥80% 测试用户可独立完成测评与一个关卡；核心流程成功率≥95%；每次干预均记录原因和策略版本；严重不合时宜干预率<10%；后测/延迟测验相较前测呈正向变化；AI 内容通过格式、答案一致性和内容检查后才能展示。学习效果目标在正式实验前不承诺统计显著性。 |

## 4. 痛点映射

| 用户任务或场景 | 当前痛点 | 根因 | 对用户的影响 | OwlOwlGo 对应机制 | 验证指标 |
| --- | --- | --- | --- | --- | --- |
| 遇到不会的题目 | 通用 AI 立即给出完整答案 | AI 不掌握用户学习状态，也没有延迟帮助目标 | 跳过思考，短期完成但难以保持和迁移 | 首次错误先再试；按状态选择轻提示、分步支架或讲解 | 无提示二次作答正确率、提示级别分布、迁移题正确率 |
| 长时间卡题 | 固定延迟或完全不提示，无法区分有效思考和无效停滞 | 缺少个人耗时基线和连续行为信号 | 挫败、放弃或随意猜测 | 比较当前耗时与个人基线，结合连续错误和修改行为升级干预 | 放弃率、超时率、干预后完成率、主观负荷 |
| 练习难度不合适 | 题库只按固定顺序或粗粒度等级出题 | 缺少知识点级掌握状态和间隔复习信息 | 任务过易导致无聊，过难导致挫败 | 根据掌握度、知识缺口、复习优先级和内容多样性选择任务 | 估计成功率区间、任务完成率、难度满意度 |
| 错题反馈 | 只显示对错或统一解析 | 未区分错误类型、尝试历史和当前提示级别 | 不知道错在哪里，容易重复犯错 | 保存错误路径，生成受约束的针对性反馈并安排迁移题 | 同类错误复发率、迁移题正确率、解释有用性评分 |
| 持续学习 | 积分奖励做题数量，容易演变为刷题 | 游戏化目标与掌握、复习和反思脱节 | 参与数据上升但学习质量不一定提高 | 奖励掌握、间隔复习、纠错和反思，限制重复刷题收益 | 连续学习天数、有效任务完成率、复习完成率 |
| 使用生成内容 | AI 可能生成错误答案、超纲内容或提前泄题 | 自由文本输出缺少结构和业务校验 | 学习误导、信任下降 | JSON Schema、答案一致性、难度/词表、提示泄露和敏感内容检查；失败时回退 | 校验通过率、答案错误率、提示泄露率、回退率 |
| 查看学习进展 | 只看到分数和做题数 | 缺少知识状态变化和干预记录 | 难以理解进步，也无法判断系统是否真正个性化 | 展示掌握变化、常见错误、提示依赖和下一步建议 | 报告查看率、建议采纳率、可解释性满意度 |

## 6. 产品描述

### 6.1 标准定位陈述

> **对于**希望利用碎片时间提高英语能力、又不希望被 AI 直接代替思考的大学生，  
> **他们**需要难度适宜的练习，并希望在真正卡住时得到逐步而非一次性揭晓答案的帮助，  
> **OwlOwlGo** 是一个 AI 驱动的游戏化 H5 英语学习伙伴，  
> **它能够**根据学习者的知识状态和实时作答过程推荐任务，并动态决定暂不介入、鼓励再试、轻提示、分步支架或完整讲解，  
> **不同于**主要依赖固定课程路径与正误反馈的传统游戏化学习产品，以及随问随答、容易直接给出完整答案的通用 AI 助手，  
> **OwlOwlGo 的关键差异**是把“帮助时机和帮助强度”作为可解释、可记录、可实验评估的核心策略，通过适宜性困难、有效失败和迁移练习促进更深层学习。

### 6.2 产品基本信息

| 项目 | 描述 |
| --- | --- |
| 产品名称 | OwlOwlGo |
| 产品类别 | AI 驱动的游戏化英语学习 H5 应用 / 智能学习伙伴 |
| 当前版本 | 工程与需求定义阶段，尚无可发布业务版本 |
| 计划首次可演示版本 | 第 10 周：MVP v0.1，完成核心学习闭环 |
| 计划首次部署 | 第 14 周：形成可在线访问的演示环境 |
| 计划迭代版本 | 第 15 周：MVP v0.2，根据测试反馈优化 |
| 计划课程发布版本 | 第 17 周：Release v1.0，用于作品答辩 |
| 主要终端 | 桌面端和移动端主流浏览器 |
| 单次使用时长 | 计划为 10–15 分钟/学习关卡 |

### 6.3 解决的问题与用户价值

| 解决的问题 | 为目标用户带来的价值 |
| --- | --- |
| AI 过早给出答案，替代学习者思考 | 保留检索、推理、自我解释和自我纠错机会 |
| 固定提示不能区分有效思考和无效停滞 | 在保持思考连续性的同时，及时终止无效挣扎 |
| 固定题序或粗粒度等级导致难度失配 | 获得更接近个人当前能力和复习需求的任务 |
| 统一解析无法针对具体错误路径 | 获得与错误类型和提示级别匹配的反馈 |
| 游戏化只奖励数量和连续登录 | 将奖励与掌握、复习、纠错和反思联系起来 |
| 用户看不懂 AI 为什么介入 | 查看简短干预原因和个人学习状态变化 |

### 6.4 解决方案组成

```text
初始测评
  → 个性化任务选择
  → 作答过程采集
  → 学习状态更新
  → 五级干预决策
  → 受约束的 AI 提示/讲解
  → 巩固与迁移练习
  → 游戏化进度和学习报告
```

| 方案组件 | 核心职责 |
| --- | --- |
| H5 学习端 | 呈现测评、任务、提示、迁移练习、游戏化反馈和报告 |
| 学习会话服务 | 编排一次学习任务从获取、作答到反馈的完整过程 |
| 学习者模型 | 维护知识点掌握度、置信度、近期错误率、耗时基线和提示依赖 |
| 任务策略 | 综合难度匹配、知识缺口、间隔复习和内容多样性选择下一任务 |
| 干预策略引擎 | 输出 0–4 级动作、决策理由、置信度和策略版本 |
| LLM 适配与校验 | 按既定级别生成提示或讲解，并检查格式、答案、难度和安全性 |
| 数据与报告 | 保存可回放的学习事件，生成个人进展与后续建议 |

## 7. 类似产品与差异化

本节比较的是产品机制类别，不对具体厂商作未经验证的功能断言。

| 产品类别 | 常见优势 | 与本问题相关的常见不足 | OwlOwlGo 的差异化 |
| --- | --- | --- | --- |
| 游戏化语言学习产品 | 课程结构成熟，积分、关卡和连续学习机制完善 | 任务路径和反馈往往以预设规则为主，对实时帮助时机刻画有限 | 将学习过程信号、五级干预和干预原因纳入核心学习闭环 |
| 通用生成式 AI 助手 | 对话灵活，解释和内容生成能力强 | 容易按请求直接给答案，缺少稳定的知识状态、课程边界和长期策略记录 | 策略与语言生成分离，由可测试策略决定何时介入和提示强度 |
| 传统在线题库 | 内容和答案相对稳定，便于练习和测评 | 常提供统一解析，个性化与过程感知较弱 | 根据个人基线、错误路径和提示依赖提供逐级支架与迁移练习 |
| 自适应练习系统 | 能根据表现调整题目难度 | 可能更关注选题，未必把延迟帮助和有效失败作为主要产品机制 | 同时优化“下一题是什么”和“当前是否帮助”，并保存策略版本供评估 |

核心差异可概括为：

1. **把不介入也视为一种主动决策**，而非系统没有响应；
2. **将任务难度和帮助时机联合建模**，而非只做推荐或只做聊天；
3. **策略与 LLM 表达分离**，使关键行为可测试、可解释、可替换；
4. **通过迁移题和延迟测验评价学习**，避免只优化即时正确率；
5. **完整记录决策依据、策略版本与后续结果**，支持回放、实验和迭代。

## 8. 成功标准与 KPI

| 类别 | 指标 | MVP 目标或计算方式 | 说明 |
| --- | --- | --- | --- |
| 可用性 | 独立完成率 | ≥80% 测试用户无需现场指导完成测评和一个关卡 | 首轮可用性门槛 |
| 稳定性 | 核心流程成功率 | ≥95% | 测评、取题、提交、干预和报告链路 |
| 性能 | 普通 API P95 | ≤500 ms | 不含外部 LLM 响应时间 |
| 干预可追踪 | 决策记录覆盖率 | 100% | 保存输入特征、动作、原因、置信度和策略版本 |
| 干预适当性 | 严重不合时宜干预率 | <10% | 由用户反馈和测试复核共同标注 |
| 学习效果 | 前后测/延迟测变化 | 方向为正；正式目标由试点数据和功效分析确定 | 首轮不预设显著性结论 |
| 迁移能力 | 迁移题正确率 | 比较不同干预条件下的差异 | 防止只记住原题答案 |
| 提示依赖 | 无提示作答与提示调用变化 | 观察是否随学习逐步降低不必要求助 | 不追求提示次数越少越好 |
| 参与度 | 关卡完成率、次日留存、连续学习天数 | 建立基线后再设迭代目标 | 不单独作为学习效果证据 |
| AI 可靠性 | 校验通过率、答案错误率、提示泄露率 | 所有生成内容先校验；具体阈值由评测集基线确定 | 失败时必须降级 |
| 隐私 | 明文密钥/敏感日志事件 | 0 | 数据最少化、环境变量和访问控制 |

## 11. 假设、约束与待验证问题

| 类型 | 内容 | 验证方式 |
| --- | --- | --- |
| 用户假设 | 大学生认为“提示不过早、卡住时能逐步帮助”具有实际价值 | 5–10 人访谈、原型任务和提示偏好排序 |
| 行为假设 | 正确率、耗时、尝试次数和求助行为足以支持首版规则策略 | 使用合成轨迹与早期测试数据回放 |
| 学习假设 | 自适应延迟帮助相较立即解析有助于迁移或保持 | 小规模对照测试和延迟测验 |
| 体验假设 | 主动提示不会被普遍视为打扰 | 记录关闭率、拒绝率和主观满意度 |
| 内容假设 | 精选题库结合受约束生成能够满足 MVP 内容需求 | 建立内容评测集并进行人工复核 |
| 工程约束 | 不进行大模型微调，首版以规则和轻量模型为主 | 在第 6 周技术评审中确认 |
| 数据约束 | 初期样本不足以训练复杂策略 | 使用保守默认策略，积累数据后再比较模型 |
| 隐私约束 | 只采集实现功能和评估所需的最少数据 | 字段审查、去标识化和删除流程测试 |

优先待确认事项：

1. 首批学习内容采用大学英语、CEFR 还是自定义知识点体系；
2. 五级干预的阈值、最大无帮助时间和用户控制方式；
3. 首轮招募规模、实验时长、知情说明和课程审批要求；
4. LLM 服务、预算、数据处理边界和降级策略；
5. “严重不合时宜干预”的操作性定义和标注流程。
